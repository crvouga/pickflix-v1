# Pickflix

Explore movies, watch trailers, write reviews, and build collaborative lists.
React/Redux frontend, Express REST API, PostgreSQL persistence.

Production: https://pickflix.chrisvouga.dev

## Hosting

[crvouga/workspace](https://github.com/crvouga/workspace) owns all hosting through
OpenTofu: Railway service, domain/DNS, shared Postgres `pickflix` schema and all
its tables (including sessions), Vault credentials, repository settings and the
image publisher workflow. This repository owns application code and its image.
No production schema migrations or table creation run at application startup.
Deploy the workspace foundation and vault roots before the fleet root.

The OpenTofu-managed publisher builds `master` using the workspace reusable CI
workflow and dispatches the image revision back to the workspace for deployment.

## Local development

Install backend and frontend dependencies with `npm ci --legacy-peer-deps` in
each directory (backend compilation runs after install). Run `npm run dev` from
the root. The frontend uses Vite; the backend serves its `frontend/dist` build in
production. Node 22 is used by the Dockerfile.

Provide the following runtime variables (never commit their values):

- `DATABASE_URL`: shared PostgreSQL connection URL; production connections set
  `search_path=pickflix` without falling back to `public`.
- `TMDB_API_READ_ACCESS_TOKEN`, `YOUTUBE_API_KEY`
- `RESEND_API_KEY`; `EMAIL_FROM` must use a verified Resend domain. Production
  uses `Pickflix <noreply@resend.chrisvouga.dev>` from the workspace inventory.
- `PICKFLIX_SECRET`, `PICKFLIX_SESSION_SECRET`: generated by workspace OpenTofu.
- `NODE_ENV=production`, `PORT=9000`, `REPOSITORY_IMPLEMENTATION=postgres`

Production requires existing tables and fails before listening if they are
missing. Local development and tests retain their existing table setup helpers;
use a disposable local database for those, never the shared production URL.

## Hosting smoke test

After `npm run tsc` in `backend`, prepare a disposable `*_integration` database
with the workspace's `pickflix-schema.hcl`. Grant a runtime role only schema
USAGE and table SELECT/INSERT/UPDATE/DELETE (no DDL), then run from `backend`:

```sh
PICKFLIX_SMOKE_DATABASE_URL='postgres://runtime@localhost/pickflix_integration?sslmode=disable' node scripts/smoke-hosting.js
```

This checks the actual production builder, health route, schema-scoped CRUD and
persistent sessions without contacting external APIs. Use Node 22.

Email remains behind the existing `IEmailLogic` port. The production and
local development builders select `ResendEmailLogic`; the SendGrid adapter is
retained and accepts its API key as an explicit dependency.

## Validation before shipping

Every pull request and merge queue revision runs `Check / Required`: a frozen
backend install and TypeScript compilation, all backend tests, frontend install
and build, and a Docker production startup test. The image test uses the
workspace's canonical Atlas schema in disposable Postgres, with a runtime role
that cannot create tables. It checks Node 22, `/health`, the frontend, database
CRUD and persistent sessions with Resend test credentials and no SendGrid key.
No production credentials or external API calls are needed.

Run the same image check locally with Docker and Atlas 1.3.0 installed:

```sh
PICKFLIX_SCHEMA_FILE=/path/to/workspace/packages/infra/tofu/foundation/pickflix-schema.hcl npm run test:hosting
```

The workspace-owned publisher runs this reusable check before pushing an image
or notifying deployment. Its OpenTofu ruleset requires `Required` on `master`.
